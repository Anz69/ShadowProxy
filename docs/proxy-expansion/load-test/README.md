# Нагрузочное тестирование (ТЗ 7.4) — как снять метрики «до/после»

Скрипты для прогона на dev/stage. Цель — зафиксировать цифры до и после оптимизаций
(возврат Mango на гейтвей, скорость пакета/триала, пинг гейтвея).

> Гонять **только на dev/stage**, не на проде. Триал одноразовый на аккаунт — для
> повторяемых замеров скорости генерации используйте сценарий `generate` на готовом пакете.

## 1. Задержка гейтвея (ТЗ 7.2) — `gateway-latency.mjs`

Node 18+, без зависимостей. Меряет время установления туннеля (CONNECT 2xx) через гейтвей.

```bash
GW_HOST=<ip-гейтвея> GW_PORT=10000 \
GW_LOGIN='package-…-user-…' GW_PASS='…' \
TARGET=example.com:443 N=200 CONCURRENCY=20 \
node gateway-latency.mjs
```

Для «накладных» сравните с прямым подключением к апстриму: запустите тот же скрипт,
указав `GW_HOST`/`GW_PORT`/креды **апстрима** (например `eu-isp.flashproxy.io:30`).
Накладные гейтвея = (p95 через гейтвей) − (p95 напрямую). Цель ТЗ: +20–50 ms.

## 2. Нагрузка на CORE API (ТЗ 7.1 / 7.3) — `api-load.k6.js`

Требует [k6](https://k6.io). Меряет p95 времени генерации прокси под параллельной нагрузкой.

```bash
BASE=https://dev.shadowproxy.io \
TOKEN='session=<кука>' \
PACKAGE_ID='<uuid пакета>' \
k6 run api-load.k6.js
```

Порог в скрипте: `proxy_generate_ms p(95) < 2000` (цель ТЗ 7.1 ≤1–2с), ошибки < 2%.

## 3. Скорость создания пакета/триала (ТЗ 7.3) — ручной замер

«Холодный» путь (первый пакет) одноразовый, поэтому проще снять из логов/таймингов:

```bash
# время ответа активации триала
curl -s -o /dev/null -w "trial: %{time_total}s\n" -X POST \
  -H "Cookie: session=<кука>" -H "Content-Type: application/json" \
  -d '{"tariffType":"RESIDENT_PREMIUM"}' \
  https://dev.shadowproxy.io/api/users/trial
```

Плюс по логам бэкенда: время от вебхука `processPaidOrder` до готового пакета.
В gateway-режиме провижининг апстрима ушёл в фон (очередь `ProvisioningQueue`),
поэтому ответ должен приходить за секунды, без «попробуйте через 15 минут».

## 4. Таблица «до/после» (заполнить на стенде)

| Метрика | ДО (`MANGO_MODE=api`) | ПОСЛЕ (`MANGO_MODE=gateway`) | Цель |
|---|---|---|---|
| Активация триала (RESIDENT_PREMIUM), время ответа | | | < 3с |
| Оформление пакета (webhook→готов) | | | секунды |
| Генерация BY_TIME-прокси, p95 (k6) | | | ≤ 1–2с |
| Накладные пинга гейтвея (p95 gw − p95 direct) | | | +20–50 ms |
| Доля ошибок генерации | | | < 2% |
| Расхождение баланс vs реальный трафик | | | < 1–2% |

> Перед прогоном «ДО» переключить `MANGO_MODE=api` и рестартить CORE; «ПОСЛЕ» —
> `MANGO_MODE=gateway` (при `USE_NODE_GATEWAY=true`).
