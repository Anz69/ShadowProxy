## 1. Главный вывод аудита

При изучении кода выяснилось, что **gateway-флоу для `RESIDENT_PREMIUM` уже построен** и
включается флагом `USE_NODE_GATEWAY=true`. То есть Task A «шаг 3» и Task B в значительной
части **уже реализованы инфраструктурно**, а корнем проблем 7.3/8.1/8.2 был не отсутствие
гейтвея, а **второй, конфликтующий источник истины** — прямой Mango API (снапшоты остатка +
синхронная доливка трафика), который параллелил/перетирал учёт гейтвея.

Поэтому Sprint 1 свёлся к тому, чтобы:
1. ввести флаг `MANGO_MODE` и **выключить конфликтующий прямой Mango API** в gateway-режиме;
2. убрать блокирующий апстрим-вызов с горячего пути **триала** (покупка уже была async);
3. зафиксировать рантук и метрики.

Где что лежит в коде (проверено):

| Что | Файл / место | Статус |
|-----|--------------|--------|
| Генерация `RESIDENT_PREMIUM` через гейтвей (`serverHost != null`, `/add-port`) | `package/package.service.ts` — ветка `isNodeGatewayEnabled()` (~775–908), идентична `MOBILE_GB` | **уже есть** (вкл. `USE_NODE_GATEWAY=true`) |
| Учёт трафика → списание баланса по типам | `proxy-node/proxy-node.controller.ts` `POST /traffic` (декремент `premiumTrafficLeft` и др. из байт гейтвея) | **уже есть** |
| Запись `TrafficLog` по пакету/часам | тот же `/traffic` (~224–268) | **уже есть** |
| Блокировка при 0 → `block-login` + SUSPENDED + sync портов | тот же `/traffic` (~200, 271–309) | **уже есть** |
| Начисление баланса при покупке/триале (локально) | `user/user.service.ts` `@OnEvent("user.distribute_traffic")` (~239) — `premiumTrafficLeft += traffic` | **уже есть** (независимо от Mango) |
| Провижининг при покупке — вне транзакции, неблокирующе | `payments/payments.service.ts` (~209–296, `void (async()=>…)()`) | **уже есть** |

## 2. Что изменено в этом спринте

### 2.1. `MANGO_MODE` (Task A, шаги 1–2) — `mango-proxy.provider.ts`
- Хелпер `isGatewayMode()`; **дефолт = `api`** (старое поведение 1:1).
- `@OnEvent("user.distribute_traffic")` → в gateway-режиме `return true` в начале:
  **не дёргаем блокирующий `/add_user_flow`** (sleep+ретраи+recovery). Локальный баланс
  при этом всё равно начисляется отдельным слушателем в `UserService` (см. таблицу выше) —
  крединг НЕ ломается.
- `@Cron updateUserBalances()` → в gateway-режиме `return`: **не тянем снапшот `/user_info`**
  (перетирание `premiumTrafficLeft` устаревшим числом = баг 8.1).
- Старый api-код полностью сохранён под флагом.

### 2.2. Скорость триала (Task C) — `user/user.service.ts:getTrial`
- В gateway-режиме: `user.distribute_traffic` (баланс + создание пакета) ждём синхронно
  (быстро, без апстрим-API), а `proxy.create_account` (создание мастер-аккаунта Mango) —
  **в фон** (`void emitAsync(...).catch(log)`). Триал больше не висит на Mango.
- Если фоновый провижининг не успел — апстрим-аккаунт **создаётся лениво при первой
  генерации** прокси (`generatePackageProxy` уже делает это, см. ~796).
- api-режим: прежний синхронный порядок сохранён.

Тот же паттерн применён ко всем точкам провижининга из ТЗ 1.4:
- `key/key.service.ts:redeemKey` — активация ключа;
- `customer-api/customer-api.controller.ts` — покупка трафика через API
  (переиспользует `UserService.isMangoGatewayMode()`).

> Покупка (`payments.service.ts`) уже была неблокирующей (provisioning в `void async`),
> поэтому отдельной правки не потребовала. Админский `modifyUserTraffic` оставлен синхронным
> (не пользовательский горячий путь, вне явного скоупа Task C).

## 3. Рантук: включение / откат

Gateway-режим Mango требует **двух** флагов (они независимы, но включать вместе):

```env
USE_NODE_GATEWAY=true     # маршрутизация наших типов (и Mango) через Go-гейтвей
MANGO_MODE=gateway        # выключить прямой Mango API (снапшоты + add_user_flow)
```

**Порядок выката (безопасно):**
1. Убедиться, что `USE_NODE_GATEWAY=true` и Mango-прокси реально ходят через `serverHost:10000`
   (Proxy.serverHost != null, трафик прилетает в `/api/proxy-node/traffic`).
2. Только после этого ставить `MANGO_MODE=gateway` и рестартить CORE.
3. Проверить: новый Mango-пакет/триал не делает запросов в Mango API на горячем пути;
   баланс убывает строго из `/traffic`; блок ровно в 0.

**Откат (любой инцидент):** `MANGO_MODE=api` + рестарт — поведение возвращается к прежнему
(прямой Mango API), весь старый код жив.

> ⚠️ НЕ включать `MANGO_MODE=gateway` при `USE_NODE_GATEWAY=false`: тогда Mango-трафик не
> считается ни снапшотом (выключен), ни гейтвеем (не подключён) → бесплатный трафик. Именно
> поэтому дефолт флага — `api`.

## 4. Task B — единый источник баланса (подтверждение)

- Источник истины для `RESIDENT_PREMIUM` в gateway-режиме — **только** декремент
  `premiumTrafficLeft` в `/traffic` + `TrafficLog`. Параллельный снапшот Mango выключен.
- Блокировка ставится **по нашему расчёту** (`newBalance === 0n` в `/traffic`), а не по ответу
  апстрима. Это и есть фикс 8.1 «трафик есть — прокси не работают» (раньше снапшот Mango мог
  обнулить/завысить баланс мимо реального счёта гейтвея).
- ProxyEmpire-типы (`PREMIUM_RESIDENTIAL`, `MOBILE`) — **не трогали**, по ТЗ.

## 6. Известные хвосты / на будущее

- ✅ **Очередь провижининга с ретраями (формальная) — СДЕЛАНО** (`provisioning/provisioning-queue.service.ts`,
  `@Global ProvisioningModule`). Cron-воркер (`@Interval 20с`) с идемпотентными повторами и
  экспоненциальным бэкоффом (5→10→20→40→60с, до 6 попыток). «Успех» для RESIDENT_PREMIUM
  проверяется по фактическому появлению `premiumUsername` (createUser глушит ошибки и не
  бросает, поэтому throw-based ретрай недостаточен). Дедуп по `userId:type`. Точки enqueue:
  триал, покупка (`payments`), активация ключа, клиентский API. Очередь in-memory; durability
  на рестарт обеспечивает ленивое до-создание при генерации (страховка сохранена). Полностью
  durable-вариант (Redis/BullMQ — `ioredis` уже в зависимостях, или таблица в БД) — апгрейд
  поверх того же интерфейса `enqueue()`.
- **Гонка двойного `createUser`.** `if (!premiumUsername.length)` не атомарен при двух
  параллельных генерациях. Низкий риск (Mango-аккаунт у юзера один); при необходимости —
  advisory-lock на userId.
- **Нужен ли вообще per-user суб-аккаунт Mango в gateway-режиме** (пулевые креды?) — открытый
  вопрос к Mango-интеграции (ТЗ 1.4.3). Пока оставлено как есть (создаётся лениво).
